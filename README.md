# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://127.0.0.1:5600 |
| 接口 | http://127.0.0.1:10600 |

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中，发起时固化清单摘要）→ 交班方与接班方各自用本地夹具密钥对「交班单id+清单摘要」签注 → 完成交班时校验双方签注与清单摘要一致后同事务整批过户 → 交班对账报告与清单/批次同源

## 签注封缄

- **签注收集**：`POST /api/handovers/{id}/attest`，双方各签各的（本地夹具密钥 HMAC-SHA256，密钥在 `fixtures/keys.json`，不接外网证书服务）；缺任一方签注，`complete` 拒绝过户，禁止先过户后补签。
- **摘要绑定**：发起时把清单业务键有序哈希固化在 `handovers.manifest_digest`；签注落库于独立表 `handover_attestations`（与清单隔离、按交班单 id 关联）。签注后清单键集合被改动的，`complete` 以「清单摘要不一致」拒绝。
- **失败闭**：签注校验与摘要比对先于一切写操作，过户与状态翻转在同一事务一次提交；失败回滚不留「已过户无签注」或「有签注未过户却标成功」。完成后签注与摘要不可改。
- **核对**：`GET /api/handovers/{id}` 返回签注双方、所签摘要、签名与清单业务键，与批次归属同库同源。
